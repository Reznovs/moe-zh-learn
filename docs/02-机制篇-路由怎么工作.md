# 02 · 机制篇：门卫（路由器）到底怎么工作

> **目标**：读完这篇，你能说清一个 token 从进 MoE 层到被某个专家处理的完整过程，
> 屏幕上的 `aux`、`z`、负载条分别在喊什么，以及出现异常时该先看哪个数字。
>
> **读法**：每节都是三段式——**直觉**（为什么要它）→ **机制**（它到底是什么）→ **判读**（数字怎么用）。
> 只想要结论可以跳过机制段。

## 1. 一个 token 的完整旅程

**直觉**：token 进了 MoE 层，第一件事不是被计算，而是被**派活**——
门口站着一个很小的"门卫"（路由器），它看一眼这个 token，决定把它交给哪几个专家。

```
        token 向量 x  (维度 d_model)
              │
   ┌──────────┴───────────┐
   │ 门卫 router：一个小的线性层  │   x → 8 个分数（8 个专家各一个）
   └──────────┬───────────┘
              │
        softmax 归一化 → 8 个概率，和为 1
              │
   取概率最大的 2 个（top-2）→ 比如 专家3 得 0.62、专家6 得 0.31
              │
   这 2 个分数再加一遍归一化 → 0.667 / 0.333（保证系数和为 1）
              │
   只看这两个专家：专家3(x) × 0.667  +  专家6(x) × 0.333
              │
   再加上永远在场的「共享专家」的输出
              │
              输出
```

**机制**：设第 l 层输入 token 向量为 x（维度 d），该层有 E 个路由专家
（Expert_1 … Expert_E，每个都是一个 FFN）和一个路由器（参数仅 d × E 的线性层）。
形式化五步：

| 步骤 | 运算 | 说明 |
|---|---|---|
| ① 打分 | `s = W_r^T · x` | 得到 E 个原始分数（logit），每个专家一个 |
| ② 归一化 | `P(x) = softmax(s)` | E 维概率分布，Σ P_i = 1 |
| ③ 选择 | `T(x) = TopK(P(x), K)` | 保留概率最大的 K 个专家；本项目 K = 2 |
| ④ 重归一化 | `g_i = P_i ÷ Σ(j∈T) P_j` | 选中权重之和为 1，输出幅度不随 K 漂移 |
| ⑤ 组合 | `y = Σ(i∈T) g_i × Expert_i(x) + Σ(j) Shared_j(x)` | 加权求和，再加共享专家 |

**细节**（四条，都要记住）：

1. **门卫是小线性层，但它决定一切**：参数极少，却分配全层计算量，
   因此是训练稳定性的关键部件；
2. **先 softmax、后 top-k、再重归一化**（Switch Transformer 系做法）。
   少了最后一步重归一化，输出幅度会随着选中组合变化而漂移；
3. **没被选中的专家这一轮完全不算**（0 FLOPs）——稀疏性的全部收益来自这条；
4. **共享专家永远参与**（DeepSeekMoE 的设计）：语法、常见搭配这类通用知识每个 token 都要，
   没必要让 8 个专家各学一遍。

## 2. 为什么需要 `aux`：门卫会自我强化

**直觉**：如果没人管，训练会自己滑向失衡：

- 某几个专家一开始碰巧表现稍好一点；
- 门卫于是更爱派活给它们 → 它们被训练得更多 → 表现更好 → 门卫更爱派……

三步就锁死了。结果是**少数专家吃撑、多数专家饿死**（论文里叫 router collapse，路由塌缩）。
代价很实在：你花了 8 个专家的显存，只用了 2 个，而且这个过程**不会让主损失看起来异常**——
所以必须用一条显式的惩罚项盯住它。

**机制**：这条惩罚项就是负载均衡损失（load balancing loss，Switch Transformer 提出）：

```
L_aux = α · E · Σ_i ( f_i × P_i )
```

它不给"预测得对不对"打分，只给"是否公平"打分。里面两个量分别从**实际结果**和**模型意愿**
两个维度度量每个专家的负载：

### 📊 f_i：实际流量份额（traffic share）

- **是什么**：一个批次里，**实际被派给专家 i 的 token 占总派活次数的比例**，
  是离散的**硬性结果**（hard assignment）；
- **怎么算**：统计专家 i 被选中 N_i 次，总派活次数为 N × K（N 为批次 token 数）：
  `f_i = N_i ÷ (N × K)`；K = 1 时用 N 归一化；
- **它回答的问题**：**"实际上，有多少 token 被送去了专家 i？"**
  f_i 过高 = 该专家成为计算瓶颈。

### 🎯 P_i：概率份额（probability share）

- **是什么**：路由网络对专家 i 的**平均倾向程度**，是可导的**软性意愿**；
- **怎么算**：门卫对每个 token 输出概率分布，再对批次求平均：
  `P_i = (1/N) · Σ_x P(x)_i`；
- **它回答的问题**：**"平均来看，门卫认为专家 i 有多重要？"**
  即使某专家这轮没被选中（f_i 小），只要 P_i 不小，说明模型对它仍有"残余偏好"，
  这种偏好需要在训练中被纠正。

### ⚖️ 为什么两者要相乘

单独用哪个都不行：

- **只用 f_i**：它来自数人头（计数），计数操作**不可导**，梯度传不到门卫身上；
- **只用 P_i**：可导，但它是"意愿"，不反映实际选择结果。

相乘之后，两个方向都被约束住：

- 专家**被过度使用**（f_i 大）且路由**过度偏好**（P_i 大）→ 乘积大，重罚；
- 专家**被闲置**（f_i 小）但路由仍有**残余偏好**（P_i 不小）→ 乘积非零，压低这份偏好。

### 均衡的标准：为什么健康值是 1.0

理想均衡时，每个专家被选中的频率与平均路由概率都相等，即 `f_i = P_i = 1/E`，代入定义式：

```
L_aux = E × Σ_i (1/E × 1/E) = E × E × (1/E²) = 1
```

所以 **L_aux 的最小值是 1**，这就是它的刻度：

| L_aux（每层均值） | 判读 |
|---|---|
| ≈ 1.0 | 路由接近均衡 |
| 1.1 ~ 1.3 | 中度偏斜，持续观察 |
| > 1.3 且持续上升 | 显著失衡，需干预（增大 α 或检查训练配置） |

系数 α（本实现 `aux_coef`）默认 **0.01**：量级必须远小于主损失项，
训练方向仍由 `L_CE` 主导，均衡项只"轻轻推一把"；α 过大会逼路由牺牲预测性能换均匀性。
总损失为：

```
L = L_CE + α · L_aux + β · L_z
```

**判读·实测对照**（同数据、同 200 步，唯一变量是 α 是否为 0）：

| 配置 | L_aux | 负载分布 |
|---|---|---|
| α = 0.01 | **1.005** | 8 个专家 0.102 ~ 0.153（基准 0.125）|
| α = 0 | 1.033 | 0.087 ~ 0.181，且第 180 步出现 0.059 的低谷 |

**关键观察**：关掉 aux 后，L_aux 只从 1.005 涨到 1.033，看起来"还行"——
真正的警报在下一节的 L_z 里。

## 3. `z-loss`：门卫的发烧计

**直觉**：门卫给出的原始分数（softmax 之前的 logits）相当于它的"自信程度"。
如果这些分数越来越大，softmax 会变得极端——一个专家 0.999，其余全是 0.0003。
这时候训练已经在往塌缩路上走了，而且 fp16 下很容易指数溢出（NaN）。
`L_z` 就是给这份自信装的**体温计**。

**机制**：L_z（ST-MoE 提出）直接约束路由 logits 的绝对幅值：

```
L_z = (1/N) · Σ_x [ log( Σ_i e^{s_i(x)} ) ]²
```

括号内是 logits 的 log-sum-exp；logits 整体变大，该项随之增大，且被平方放大。
它防两件事：

1. **softmax 饱和**：logits 幅值过大 → 分布趋近赢家通吃 → 落选专家几乎不再获得梯度，
   这正是塌缩的典型前兆；
2. **数值安全**：fp16 训练下，过大的 logits 容易指数溢出，直接 NaN。

**判读**：健康区间约 1 ~ 3 且平稳；**无故翻倍就是失稳的早期信号**：

| 配置 | L_z（每层均值） | 判读 |
|---|---|---|
| α = 0.01（开均衡损失）| ≈ **1.91** | 平稳、健康 |
| α = 0（关均衡损失）| ≈ **6.54** | 翻了三倍多，门卫正在变得极端自信 |

由此得到本篇最重要的一条方法论：**先发烧、后塌缩**——
失衡的最早证据是 L_z 上涨，而不是负载分布变化。
诊断顺序：**先看 L_z，再看利用率/熵**（详见第 4 课）。

## 4. 屏幕上的"专家负载条"怎么读

**直觉**：训练日志每若干步会把每一层的路由状态压成一行，像一份体检报告：

```
    层1 专家负载 ▆▃▄▆▄▃▄▄  (均匀=0.125) 路由熵=1.533/2.079
```

**判读**：逐字段拆开看。

| 字段 | 定义 | 判读标准 |
|---|---|---|
| `▆▃▄▆▄▃▄▄` | 8 个专家各自的 f_i（实际流量份额），画成 8 根竖条 | 健康区间 `f_i ∈ [0.5, 2] × (1/E)`，8 专家即 **0.0625 ~ 0.25**；低于 `0.25/E`（8 专家为 **0.031**）= 饥饿警告；高于 `2/E` = 热点 |
| `(均匀=0.125)` | 绝对基准 1/E | 所有 f_i 的理想值 |
| `路由熵=1.533/2.079` | `H = −Σ_i p_i · ln p_i`（p_i 为批次平均路由概率） | 上限 `ln E = 2.079`（8 专家）；经验健康区间 **(0.7 ~ 0.9) · ln E**；贴近上限 = 路由未分化（近似随机均匀）；明显偏低 = 路由专断化 |

同一行的**三种典型形态**（逐层检查）：

| 形态 | 负载条 | 熵 | 判读 |
|---|---|---|---|
| 塌缩 | `▇▁▁▁▁▁▁▁` | 远低于 ln E | 失败，立即干预 |
| 未分化 | `▃▃▃▃▃▃▃▃` | 贴近 ln E | 无信息：路由近似随机，或 α 过大致使路由失去专一性 |
| 健康 | `▆▃▄▆▄▃▄▄` | (0.7 ~ 0.9) · ln E | 围绕基准小幅波动，存在稳定偏好 |

**要点**：任何单一指标都不充分。主损失 `L_CE` 对路由健康几乎不敏感，
L_z 最早报警，负载与熵用来确认塌缩是否真的发生——三项联动判读。

## 5. 术语速查

| 术语 | 一句话直觉 | 技术要点 / 代表做法 |
|---|---|---|
| **top-k 路由** | 每个 token 用几个专家 | 最常用 K = 2；K=1 更省但更容易塌；K 增加则计算线性上升。Mixtral 8x7B 用 K=2 |
| **细粒度专家** | 不用 8 个大专家，改用很多小专家 | 增大 E、缩小单个专家规模，同激活预算下可选组合数 C(E,K) 急剧增加，路由表达力更强；DeepSeek-V3 用 256 路由专家 top-8 |
| **共享专家** | 永远上班的那个专家 | 无条件激活，承载通用知识，减少路由专家之间的重复学习（DeepSeekMoE 提出）|
| **激活率** | 干活的参数 ÷ 全部参数 | 用**实测值**而非 K/E：注意力、嵌入、共享专家总是激活；本项目 L0 实测 **41%**，公式给的是 25% |
| **稀疏度** | 激活率的倒数 | 稀疏度 4 = 每个 token 只用 1/4 的参数 |
| **容量因子 / token dropping** | 给每个专家一个"每批最多接多少 token"的筐 | 筐满则丢弃超出的 token；单机实现可略过，多卡并行才必须（GShard / Switch）|
| **专家并行** | 把专家分到不同 GPU 上，token 用网络传过去 | all-to-all 通信是大规模 MoE 最大的工程瓶颈（Megablocks 等）；本项目单卡不涉及 |

## 6. 为什么有些层适合放 MoE，有些层不适合

**直觉**：MoE 的收益来自"不同 token 需要不同的专家"。如果某一层的活是所有人都一样，
门卫在这里就**没得分**，只会制造噪声。

**机制**：放置依据是各层表征的可分性：

- **浅层**处理局部、通用特征（词形、拼写、高频搭配）：各 token 需求高度一致，
  不存在可供路由利用的分化结构；
- **中后层**处理语义、领域、文体：token 需求开始分化，专家分工有实际收益。

实践对照：

| 模型 | 放置策略 |
|---|---|
| DeepSeek-V3 | 61 层中**前 3 层稠密**，其余 58 层 MoE（256 路由 + 1 共享，top-8）|
| GLM-4.5 | 同样保留前几层稠密（理由：早期稀疏路由的不稳定性会干扰底层特征形成）|
| Llama 4 Maverick | MoE 层与稠密层**隔层交替** |
| 稀疏上采样（upcycling，Google ICLR 2023）| 仅改造**最后少数层**即可获得收益 |

本项目 L0（4 层）对所有层开启 MoE 属于教学简化——层数太少，分不出前后；
规模化时（第 6 课）应先把浅层改回稠密。

## 7. 要点汇总

1. **路由流程**：线性打分 → softmax → top-k → 选中项重归一化 → 加权求和（+共享专家）；
2. **`L_aux = α · E · Σ_i (f_i × P_i)`**：f_i 是不可导的实际结果（负责"定罪"），
   P_i 是可导的意愿（负责"给方向"）；完全均衡时 L_aux = 1；
3. **L_z** 约束 logits 幅值，防 softmax 饱和与 fp16 溢出，**对失稳的响应早于负载指标**；
4. **判读顺序**：L_z（先行）→ 负载 f_i / 熵（确认）→ L_CE（不反映路由健康）；
5. **MoE 只宜放中后层**：浅层无可分结构，前沿系统普遍保留浅层稠密。

## 自测三问

1. L_aux 里为什么必须同时有 f_i 和 P_i？只用其中一个各有什么缺陷？
2. E = 8 时某个专家 f_i = 0.058，这层路由算健康吗？依据是哪个阈值？
3. α = 0 的对照里，L_aux 只有 1.03，而 L_z 从 1.91 涨到 6.54——应该优先依据哪项判定风险？为什么？

**答案要点**

1. f_i 来自计数、**不可导**，无法反向传播；P_i 可导但只反映意愿、脱离实际选择。
   相乘才能"在可导的前提下约束真实负载"。
2. 健康下限是 `0.5 × 1/8 = 0.0625`，饥饿阈值是 `0.25 × 1/8 ≈ 0.031`；
   0.058 落在两者之间 → **警告带**：尚未塌缩但已偏斜，需结合熵与 L_z 综合判断。
3. 依据 **L_z**——它对失稳的响应早于负载分布指标（本例 aux 几乎没动，z 已翻三倍），
   说明门卫正在变得极端自信，是塌缩的前兆。
