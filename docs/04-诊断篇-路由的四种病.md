# 04 · 诊断篇：路由的四种病（附我们亲手做出来的病例）

> 目标：学会给 MoE 做体检。读完这篇，你拿到任何一次 MoE 训练日志，
> 都能在 1 分钟内判断"这次训练是健康的、还是在骗我"。

---

## 0. 先记住这句话

> **MoE 的损失曲线会骗人。**
> 稠密模型训练失败时，损失会立刻变丑；MoE 训练失败时，损失可能依然漂亮，
> 但一半专家已经饿死了——你花了 8 个专家的显存，只买到 2 个。

所以诊断 MoE 要看的不是 `ce`，而是**路由体检三件套**：

| 体检项 | 健康表现 | 在哪看 |
|---|---|---|
| **专家负载条** | 围绕 `均匀=0.125` 轻微起伏，最矮的不低于均匀的 1/2 | 日志的 `专家负载` 行 / `analyze.py --mode util` |
| **路由熵** | 稳定在 ln(8)=2.079 的 70–90% 左右 | 同上 |
| **aux / z** | aux ≈ 1.0 且平稳；z 缓慢变化，不翻倍 | 日志的 `aux … z …` |

---

## 1. 病例 A：路由塌缩（router collapse）—— 最经典的病

**症状**
- 负载条出现"空格"：`██▁▁▁▁▁▁`，某个专家份额掉到均匀值的 1/2 以下
- `z` 值持续上升（我们的实测：**1.91 → 6.54**）
- 路由熵下降（门卫越来越"专断"）
- **损失曲线看起来完全正常，甚至更好**

**病因**：自我强化循环。
门卫稍微偏爱专家 3 → 专家 3 得到更多训练 → 表现更好 → 门卫更偏爱它 → …
一旦进入这个正反馈，其他专家永远学不动（因为收不到样本）。

**处方（按顺序试）**

1. 开/加大均衡损失：`--aux_coef 0.01`（默认）→ 偏科时提到 `0.03`，极端情况 `0.1`
2. 用 top-2 而不是 top-1（多一个"副手专家"，显著降低塌缩概率）
3. 保留共享专家（`--n_shared 1`，默认）：让通用知识有固定去处，减小路由压力
4. 降学习率 / 延长 warmup（门卫早期太激进是常见诱因）

**我们实测的真实病例**（同一份数据、同样 200 步，只改 `--aux_coef`）：

| 指标 | 健康（aux_coef=0.01） | 生病（aux_coef=0） | 判读 |
|---|---|---|---|
| val 损失 ce | 0.0139 | **0.0132（更好！）** | ⚠️ 损失完全没报警 |
| 利用率 min / max | 0.102 / 0.153 | **0.087 / 0.181** | 有偏，但还没到极端 |
| aux（每层均值） | 1.005 | 1.033 | 只差一点点 |
| **z（每层均值）** | **1.91** | **6.54（3.4 倍）** | ✅ **唯一明显报警的指标** |
| 层3 路由熵 | 1.59 / 2.079 | 1.44 / 2.079 | 门卫确实变专断了 |

**这张表是本文档最值钱的东西**，它说明三件事：

1. **损失不是健康指标**：病的那次损失还更低。
2. **z 比利用率更早报警**：利用率只是"有点偏"，z 已经翻了三倍多。
3. **小模型小语料上，塌缩是"趋势"而不是"灾难"**：
   我们的演示语料只有 3.8 万字符，模型 200 步就背下来了，门卫没有强动机去分化。
   想看**极端**塌缩，需要更真实的语料 + 更长训练（见第 5 节实验步骤）。

## 2. 病例 B：过度均匀（over-uniform）—— 佛系门卫

**症状**
- 路由熵几乎贴满 2.079（门卫等于在**随机乱派**）
- 文体路由表里每个专家在每种文体上的份额几乎一样（都是 12.5% 左右）
- aux 极接近 1.0，非常"好看"
- 但换到真任务上，模型能力明显不如同等激活参数的稠密模型

**病因**：均衡损失太大（把门卫推平了），或数据太单一（所有 token 需求相同，本就没有可分的活），
或训练太短（还没来得及分化）。

**处方**：把 `aux_coef` 调小（0.01 → 0.003）；换更多样的语料；训练更久。

> 🎯 **别自我欺骗**：我们 `--source builtin` 那 948 字的演示语料，
> 天然就是病例 B——门卫无事可做。
> 所以**看专家专业化必须在真语料上做**（维基/新闻/代码混合）。这是本教程最容易踩的坑：
> 用玩具数据得出结论"MoE 没用"。

---

## 3. 病例 C：z 爆炸（门卫发烧）

**症状**：`z` 快速攀升（比如 2 → 10 → 30），随后出现 ce 抖动、fp16 溢出警告，最终 NaN。

**病因**：门卫原始分数（logits）越来越大。
它的绝对值没有物理意义，只影响 softmax 的陡峭程度；一旦过大，
softmax 输出变成 1/0 的硬选择，梯度几乎消失，训练就崩了。

**处方**

1. 提高 `--z_coef`（默认 1e-4，可到 1e-3）
2. 降学习率（`--lr`）或延长 warmup（`--warmup_steps`）
3. T4/P100（无 bf16）用 fp16 时更易溢出：开关自动加了梯度缩放，别手动关掉
4. 检查数据里有没有异常长的样本（会推高 logits 方差）

---

## 4. 病例 D：专家不分化（no specialisation）

**症状**：整体利用率很均衡、熵也正常，但**文体路由表全平**——
代码、故事、百科在每个专家上的份额几乎一样。

**病因**：数据同质（都在同一领域）、专家太少或太小、MoE 层放得太靠前、训练太短。

**处方**：
- 数据混合多种来源（这是最有效的一招）
- 规模化后把 MoE 放到**中后层**（前几层放稠密），这是 DeepSeek-V3 的做法
- 增加专家数量 + 减小单个专家（细粒度专家），让门卫有更细的可选空间

> 注意：**不分化不算"病"**，只要损失正常，模型依然能用，只是没吃到 MoE 的额外好处。
> 在免费算力这个规模上，这才是常态——别指望 10M 模型出现"代码专家"这种浪漫故事。

## 5. 5 分钟体检流程（照做即可）

```bash
# ① 训练时打开日志，盯三样：aux ≈1.0? z 平稳? 利用率 min 是否 ≥ 均匀值的一半?
python train.py --preset L0 --data_dir data/demo --out_dir out_L0 --max_steps 2000

# ② 存档后做完整体检
python analyze.py --ckpt out_L0/latest.pt --data_dir data/demo --mode all

# ③ 人为制造一次病，和健康样本对比（强烈建议做一次）
python train.py --preset L0 --data_dir data/demo --out_dir out_bad --max_steps 2000 --aux_coef 0
python analyze.py --ckpt out_bad/latest.pt --data_dir data/demo --mode util
```

**体检结论怎么写**（拿去和队友/自己交流的模板）：

```
配置：L0 / 真语料 xxx / 步数 xxx
ce：x.xxx（平台）        健康判据：是否还在降
aux：x.xx（每层均值）    健康判据：≈1.0
z：xx.x 走势             健康判据：是否翻倍
利用率 min/max：x.xx/x.xx  健康判据：min ≥ 0.5×均匀
文体表：是否有明显偏好   健康判据：至少一列出现 >1.6× 均匀的偏斜
结论：健康 / 偏科（需调大 aux）/ 塌缩（需回滚超参重训）/ 不分化（数据太单一）
```

---

## 6. 本文结论

> MoE 的健康不看损失，看路由：负载条、路由熵、aux、z。
> 塌缩最危险，因为损失不会报警，而 z 是最早的警报器；
> 过度均匀最隐蔽，多半是数据太单一或 aux 太大；
> 在免费算力的小规模上，"专家不分化"是常态，不必强求。
