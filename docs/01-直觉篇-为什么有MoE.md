# 01 · 直觉篇：为什么会有 MoE

> 目标：读完这篇，你能用大白话给人讲清楚"MoE 到底改了模型的哪个零件、为什么大厂都用它、它的代价是什么"。
> 不需要任何代码背景。

---

## 1. 先看一个模型里参数都花在哪

一个 Transformer 大模型，一层里就两个零件：

```
输入 → [注意力 attention] → [前馈网络 FFN] → 输出
```

- **注意力**：负责"看别的词"。参数少（大约占 1/3）。
- **FFN**：负责"加工知识"。参数多（**大约占 2/3**）。

一句话直觉：注意力像**读题**，FFN 像**检索并调用脑中知识**。

参数越多，模型能装的知识越多，但也越慢、越吃显存。

---

## 2. MoE 的改动只有一处：把 FFN 复制 N 份

```
普通 FFN（稠密）
  每个词 → 同一个 FFN

MoE（稀疏）
  每个词 → 门卫 router → 从 8 个 FFN 里挑 2 个 → 结果加权相加
```

这些被复制的 FFN 就叫**专家（expert）**。挑几个就叫 **top-k**。
承担责任的那个"门卫"叫**路由器（router）**或**门控（gate）**。

**关键**：不是每个词都要 8 个专家都算一遍。8 个专家都在**硬盘/显存里躺着**，
但每个词只**唤醒 2 个**。这就是"稀疏"的含义。

> 打个比方：一家医院有 8 个科室（专家）。你看病只挂 2 个科的号（激活），
> 但医院必须把 8 个科室都建起来（参数、显存）。**楼是满的，人只来一部分。**

---

## 3. 两本账：一定要分清

这是学 MoE 最容易混的地方，请把这两行背下来：

| 账本 | 由谁决定 | 决定了什么 |
|---|---|---|
| **总参数**（全部专家加起来） | 专家的**数量** | 显存、模型体积、下载时间 |
| **激活参数**（每个词实际用到的） | top-**k** | 计算量（FLOPs）、速度 |

公式只用记一个：

```
训练总计算量 ≈ 6 × 激活参数 × 训练token数
```

**6** 是"前向 + 反向"的经验系数（1 份前向算 + 2 份反向算，各按一次乘加算 2 次）。
你只要记住：**算力看激活参数，显存看总参数。**

### 用本项目的真实数字验一遍

我们最迷你的预设 L0：8 个专家、每个词用 2 个 + 1 个共享专家。

```
总参数  = 10.65M   ← 显存按这个算
激活参数 =  4.36M   ← 速度按这个算
```

咦，8 个专家只用 2 个，为什么激活不是 10.65 ÷ 4 ≈ 2.7M？

**因为词嵌入、注意力、共享专家每步都在算，只有 FFN 是稀疏的。**
所以真实激活率是 41%，而不是教科书上那个 `k/E = 2/8 = 25%`。

> 这是第一个"指标陷阱"：**公式给的是理想值，实测常有出入，永远以实测为准。**
> （第 4 课还有更狠的陷阱：指标好看但模型坏了。）

---

## 4. 为什么大厂愿意付代价用 MoE

同一份算力预算下，MoE 可以做到：

- **训练更快**：每个 token 只算 1/5、1/10 的参数 → 同样的 token 数，时间缩短 5–10 倍；
  省下来的时间要么喂更多数据，要么把模型容量再堆大。
- **同样的钱，换来更大的"脑容量"**：DeepSeek-V3 总参数 671B，但每个词只激活 37B，
  如果它是稠密的，训练和推理成本会高到不可接受。
- **专家有可能自然分工**：有研究（含我们第 6 课讲的实验 E6）观察到不同专家倾向处理不同内容（代码/数学/某类语言）。

**代价**：

- 显存必须装下**所有**专家（所以 MoE 的"省"是省算力，不省显存）；
- 路由需要额外训练技巧（均衡损失），否则会**塌缩**：门卫偏爱某几个专家，其他专家白拿工资；
- 多卡训练时要来回搬运 token，通信开销大（我们单卡小模型没这个烦恼）。

---

## 5. 什么时候 MoE 反而不如稠密模型（重要！）

这是很多教程不讲的实话：

- **总参数相同、数据相同** → **稠密通常更好**。因为稠密模型每个词都用上全部参数，
  而 MoE 每个词只用一部分，每个专家见到的样本只有 1/E。
- **激活参数相同**（也就是算力相同）→ **MoE 更好**。这才是 MoE 存在的理由：用同样的算力换更大容量。
- **显存受限** → 稠密更好（MoE 要把专家全装下）。

还有一个"数据需求量"的门槛：MoE 因为参数多，**需要远多于稠密模型的数据**才能喂饱。
业界成熟 MoE 的训练 token ÷ 激活参数 大约在 **400 倍**（DeepSeek-V3）到 **3900 倍**（OLMoE）之间。
而免费算力上我们最多做到 30–60 倍 —— 所以小规模时，MoE 的质量优势**吃不到**，
我们学它，是为了**掌握工程和诊断能力**（这正是本项目的目的）。

---

## 6. 一篇文档的结论（可以直接抄给别人的版本）

> MoE 把 Transformer 里的 FFN 复制成 N 个"专家"，加一个门卫 router，
> 每个词只送给 top-k 个专家算。它用**显存**换**算力**：
> 总参数决定显存，激活参数决定速度。
> 在激活参数相同（算力相同）的前提下，MoE 能塞进几倍的容量，这就是它唯一的、但足够大的价值；
> 而代价是路由需要被监控和调教，否则专家会饿死。
