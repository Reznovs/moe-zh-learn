## 1. 公式卡（只要这六个）

| 公式 | 含义 | 白话 |
|---|---|---|
| `训练算力 ≈ 6 × 激活参数 × token 数` | 训练总 FLOPs | 6 = 前向 2 + 反向 4（等价系数） |
| `token 数 ≈ 20 × 激活参数` | Chinchilla 配比 | "水桶装水"：模型多大，就得喂多少 token |
| `激活率 = 激活参数 ÷ 总参数` | 稀疏程度 | **用实测值**，别用 k/E（小模型差很多） |
| `aux = E × Σ f_i × P_i` | 均衡损失 | 均匀时 ≈ 1.0，越大越偏科 |
| `z = mean(logsumexp(router_logits)²)` | 门卫发烧计 | 它先报警，再看利用率 |
| `MoE 提速倍数 ≈ 1 ÷ 激活率` | 与"等容量稠密模型"相比 | 激活率 20% ⇒ 约 5 倍（乐观口径） |

**常用刻度**：ln(8)=2.079；8 专家均匀负载 = 0.125；16 专家均匀 = 0.0625。

## 2. 体检指标对照表

| 指标 | 健康 | 报警 | 说明 |
|---|---|---|---|
| `ce` / `val_ce` | 下降后平坦 | 上升 / NaN | **不是** MoE 的健康判据 |
| `aux`（每层均值） | ≈ 1.0，平稳 | >1.3 且上升 | 偏科 |
| `z`（每层均值） | 1–3，平稳 | **翻倍以上** | 最早的塌缩警报 |
| 利用率 min | ≥ 0.5 × 均匀值 | < 0.25 × 均匀值 | 有专家在饿死 |
| 路由熵 | 均匀熵的 70–90% | 贴满（佛系）或很低（独裁） | 见病例 B / A |
| 文体路由表 | 有局部偏好（>1.6×均匀） | 全平 | 专家未分化 |

## 3. 术语中英对照

| 中文 | 英文 / 缩写 | 一句话解释 |
|---|---|---|
| 混合专家 | MoE (Mixture of Experts) | 用多个 FFN 代替一个大 FFN，逐 token 选择 |
| 专家 | expert | 被复制的 FFN 单元 |
| 路由 / 门控 | router / gate | 决定每个 token 去哪个专家的小线性层 |
| top-k | top-k routing | 每个 token 用几个专家（常用 2） |
| 负载均衡损失 | load balancing loss / aux loss | 防止门卫偏科的惩罚项 |
| z 损失 | router z-loss | 防止路由分数爆炸的惩罚项 |
| 共享专家 | shared expert | 永远参与的那个专家（DeepSeekMoE 提出） |
| 细粒度专家 | fine-grained experts | 多而瘦的专家（如 256 个），组合更灵活 |
| 稀疏度 | sparsity | 激活率的倒数；稀疏度 4 = 只用 1/4 参数 |
| 激活参数 | active / activated parameters | 每个 token 实际参与运算的参数 |
| 容量因子 / 丢 token | capacity factor / token dropping | 每专家限量的筐，满了就丢 token（多卡大规模才需要） |
| 专家并行 | expert parallelism | 把专家分到多张卡，token 跨卡传输（all-to-all） |
| 稀疏上采样 | sparse upcycling | 稠密模型 → 复制 FFN 成专家 → 继续训练 |
| 稠密 | dense | 普通的、所有参数都参与计算的模型 |

## 4. 模型规模锚点（公开报告值，供建立直觉）

| 模型 | 总参数 | 激活参数 | 路由结构 | token/激活参数 |
|---|---|---|---|---|
| Mixtral 8x7B | 47B | 13B | 8 专家 top-2 | — |
| OLMoE | 6.9B | 1.3B | 64 专家 top-8 | ≈ 3900× |
| DeepSeek-V3 | 671B | 37B | 256 路由专家 + 1 共享，top-8；前 3 层稠密 | ≈ 400× |
| Kimi K2 | 1.04T | 32B | 384 专家 top-8 | ≈ 480× |
| **我们的 L0** | 11.9M | 5.6M | 8 专家 top-2 + 1 共享 | ≈ 0.6× |

> 最后一行的"0.6×"就是全部问题的答案：**我们的数据量连激活参数的 1 倍都不到**，
> 所以吃不到 MoE 的质量红利，只能吃它的工程经验。

## 6. 踩坑清单（按踩到的概率排序）

1. **用小语料跑出漂亮损失就以为成功了** → 那是背诵。看 val/train 的差距。
2. **关掉或忘记均衡损失** → 门卫偏科；z 会先涨。
3. **只看损失，不看路由** → 塌缩可以完全不影响损失。
4. **用玩具语料判断"专家不分工"** → 数据本身没有可分性，结论无效（病例 D）。
5. **MoE 层放太多/太靠前** → 前几层放 MoE 只会增加噪声（DeepSeek-V3 前 3 层保持稠密）。
6. **T4 上用 bf16** → 不支持，脚本会自动退到 fp16；手动改要小心溢出。
7. **训练很久才存档** → 免费算力会话随时被踢，20–30 分钟一存。
8. **把 Colab 两个账号当集群跑** → 违反服务条款，也不现实；把 Colab 当杂活车道。
9. **感觉 MoE 应该更快** → 只有在"和等容量稠密模型比"时才快；和等激活稠密比，它更慢（多了路由和多次专家调用）。
10. **直接开大** → 先用 10M 把流程和诊断工具跑顺，再上 1B 级。

## 7. 物理直觉小结（合上书也想得起的三句话）

1. **MoE 用显存换算力**：总参数决定显存，激活参数决定速度。
2. **门卫需要被管**：aux 让它别偏心，z 是它的体温计。
3. **规模决定收益**：数据不够时，MoE 的容量只是摆设；训练 MoE ≈ 训练"一个会偷懒的模块 + 一套体检流程"。
